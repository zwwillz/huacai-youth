# 后台渐进加载回归检查

后台页面每次新增或重构后，至少检查一次“点击后的第一帧”和“数据完成后的最终帧”。

验收标准：

- 页面第一帧与最终帧使用同一个 page-owned View / presentation component。
- Sidebar、Topbar、页面 Hero、固定标题、Tab、筛选、发布条、表头和卡片外框不应因为数据返回而换成另一套结构。
- 允许变化的内容仅限真实数据位，例如赛事名称、人数、状态、比赛行、排名行、时间和台号。
- 数据未完成时使用 `—`、`正在读取` 或安全空数据；不得显示另一套灰色 Skeleton / 近似页面。
- 页面最终 CSS 必须在第一帧已经生效，不能等目标 Route 完成后再改变字号、间距、宽高或布局。
- Loading 空数据不得触发保存、发布、抽签、比分确认等写操作，也不得长期污染正式业务缓存。
- 未授权用户只能看到固定结构和安全占位，不得通过 Loading 泄露赛事、球员、账号或比赛数据。
- 大签表、比分、晋级、最终排名等重数据仍按用户意图加载，不做全后台自动预取。

推荐浏览器检查链路：

`工作台 → 赛事管理 → 内容发布 → 竞赛执行 → 抽签 → 赛程 → 比分 → 晋级 → 最终排名 → 球员档案 → 积分排名 → 账号与权限 → 操作日志`

每次点击重点观察：**页面是否只是数据原位补齐，而不是“先出现一页，再换成另一页”。**
